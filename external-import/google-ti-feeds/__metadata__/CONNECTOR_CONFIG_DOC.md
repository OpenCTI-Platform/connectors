# Connector Configurations

Below is an exhaustive enumeration of all configurable parameters available, each accompanied by detailed explanations of their purposes, default behaviors, and usage guidelines to help you understand and utilize them effectively.

### Type: `object`

| Property | Type | Required | Possible values | Default | Description | Examples |
| -------- | ---- | -------- | --------------- | ------- | ----------- | -------- |
| OPENCTI_URL | `string` | ✅ | Format: [`uri`](https://json-schema.org/understanding-json-schema/reference/string#built-in-formats) |  | The URL of the OpenCTI platform instance | ```http://localhost:8080```, ```https://opencti.example.com``` |
| OPENCTI_TOKEN | `string` | ✅ | Length: `string >= 1` |  | Authentication token for accessing the OpenCTI API |  |
| GTI_API_KEY | `string` | ✅ | Format: [`password`](https://json-schema.org/understanding-json-schema/reference/string#built-in-formats) |  | API key for authenticating with the Google Threat Intelligence service |  |
| CONNECTOR_TYPE | `const` |  | `EXTERNAL_IMPORT` | `"EXTERNAL_IMPORT"` | Type of connector - must be EXTERNAL_IMPORT for import connectors |  |
| CONNECTOR_NAME | `string` |  | Length: `string >= 1` | `"Google Threat Intel Feeds"` | Display name for the connector |  |
| CONNECTOR_SCOPE | `array` |  | string | `["report", "location", "identity", "attack_pattern", "domain", "file", "ipv4", "ipv6", "malware", "sector", "intrusion_set", "url", "vulnerability", "campaign"]` | Comma-separated list of OpenCTI entity types that this connector can import |  |
| CONNECTOR_LOG_LEVEL | `string` |  | `debug` `info` `warn` `warning` `error` | `"error"` | Logging level for the connector |  |
| CONNECTOR_DURATION_PERIOD | `string` |  | Format: [`duration`](https://json-schema.org/understanding-json-schema/reference/string#built-in-formats) | `"PT2H"` | ISO 8601 duration between connector runs (e.g., PT2H for 2 hours) |  |
| CONNECTOR_QUEUE_THRESHOLD | `integer` |  | `1 <= x ` | `500` | Maximum number of messages in the connector queue before throttling |  |
| CONNECTOR_TLP_LEVEL | `string` |  | `WHITE` `GREEN` `AMBER` `RED` `WHITE+STRICT` `GREEN+STRICT` `AMBER+STRICT` `RED+STRICT` | `"AMBER+STRICT"` | Traffic Light Protocol (TLP) marking for imported data |  |
| GTI_API_URL | `string` |  | Format: [`uri`](https://json-schema.org/understanding-json-schema/reference/string#built-in-formats) | `"https://www.virustotal.com/api/v3"` | Base URL for the Google Threat Intelligence API |  |
| GTI_IMPORT_SOFTWARE_TOOLKITS | `boolean` |  | boolean | `false` | Whether to enable importing software toolkit data from GTI |  |
| GTI_SOFTWARE_TOOLKIT_IMPORT_START_DATE | `string` |  | Format: [`duration`](https://json-schema.org/understanding-json-schema/reference/string#built-in-formats) | `"P1D"` | ISO 8601 duration string specifying how far back to import software toolkits (e.g., P1D for 1 day, P7D for 7 days) |  |
| GTI_SOFTWARE_TOOLKIT_ORIGINS | `array` |  | `All` `partner` `google threat intelligence` | `["google threat intelligence"]` | Comma-separated list of software toolkit origins to import, or 'All' for all origins. Allowed values: All, partner, google threat intelligence | ```All```, ```partner```, ```google threat intelligence``` |
| GTI_SOFTWARE_TOOLKIT_EXTRA_FILTERS | `array` |  | string | `[]` | Optional list of additional filters to add to query when fetching software toolkits | ```name:Cobalt Strike``` |
| GTI_SOFTWARE_TOOLKIT_SUBENTITIES | `array` |  | `malware_families` `attack_techniques` | `["malware_families", "attack_techniques"]` | Comma-separated list of sub-entity types to fetch and link for each software toolkit. An empty list disables sub-entity fetching entirely for software toolkits, which can help reduce API quota usage. Allowed values: malware_families, attack_techniques | ```malware_families```, `````` |
| GTI_IMPORT_INDICATORS | `boolean` |  | boolean | `false` | Whether to enable importing IOC indicator data from GTI via Steady-State IOC Deltas API |  |
| GTI_INDICATOR_TYPES | `array` |  | `file` `ip` `url` `domain` | `["file", "ip", "url", "domain"]` | Comma-separated list of IOC types to import. Allowed: file, ip, url, domain |  |
| GTI_INDICATOR_IMPORT_START_DATE | `string` |  | Format: [`duration`](https://json-schema.org/understanding-json-schema/reference/string#built-in-formats) | `"P1D"` | ISO 8601 duration string specifying how far back to import indicators on first run (e.g. P1D for 1 day, P7D for 7 days). Must be greater than 1 hour (the IOC delta package granularity). |  |
| GTI_INDICATOR_MIN_SCORE | `integer` |  | `0 <= x <= 100` | `50` | Minimum GTI score (0-100) an indicator must have to be imported via the Steady-State IOC Deltas API. Indicators with a lower score are discarded. Indicators without a score are always imported. Set to 100 or leave unset (None) to disable the filter entirely. |  |
| GTI_INDICATOR_REQUIRE_MALWARE_FAMILY | `boolean` |  | boolean | `false` | Only import indicators that have at least one association with a Malware Family. Combined with indicator_require_threat_actor using OR logic, and with indicator_min_score using AND logic. |  |
| GTI_INDICATOR_REQUIRE_THREAT_ACTOR | `boolean` |  | boolean | `false` | Only import indicators that have at least one association with a Threat Actor. Combined with indicator_require_malware_family using OR logic, and with indicator_min_score using AND logic. |  |
| GTI_INDICATOR_SUBENTITIES | `array` |  | `malware_families` `threat_actors` `software_toolkits` `attack_techniques` | `["malware_families", "threat_actors", "software_toolkits"]` | Comma-separated list of sub-entity types to link to each indicator. The IOC delta packages already embed these relationships, so this setting does not change API quota usage: it only controls which related entities and relationships are sent to OpenCTI. attack_techniques is excluded by default because it accounts for most of the relationships of the IOC feed. An empty list imports the indicators without any relationship. Allowed values: malware_families, threat_actors, software_toolkits, attack_techniques | ```malware_families,threat_actors,software_toolkits,attack_techniques```, `````` |
| GTI_INDICATOR_INFRASTRUCTURE | `array` |  | `resolutions` `subdomains` `siblings` `downloaded` `communicating` `contacted` `serving_ip` `embedded` `referrer` | `[]` | Comma-separated list of infrastructure relationships of the IOC delta entries to import as observables linked to the IOC observable (described with the GTI relationship when relationship_descriptions is enabled). The delta packages already embed them, so this setting does not change API quota usage. The linked observables have no GTI verdict: they are context, not indicators. resolutions: domain resolves-to IP. subdomains, siblings: related domains. downloaded, communicating, referrer: files downloaded from, communicating with or referencing a domain or IP. contacted, embedded: domains and IPs contacted by or embedded in a file. serving_ip: last IP serving a URL. An empty list imports none. Allowed values: resolutions, subdomains, siblings, downloaded, communicating, contacted, serving_ip, embedded, referrer | ```resolutions,contacted,downloaded,serving_ip```, `````` |
| GTI_INDICATOR_INFRASTRUCTURE_LIMIT | `integer` |  | `1 <= x ` | `10` | Maximum number of observables imported per infrastructure relationship list of an IOC delta entry (see indicator_infrastructure). |  |
| GTI_IMPORT_CAMPAIGNS | `boolean` |  | boolean | `false` | Whether to enable importing campaign data from GTI |  |
| GTI_CAMPAIGN_IMPORT_START_DATE | `string` |  | Format: [`duration`](https://json-schema.org/understanding-json-schema/reference/string#built-in-formats) | `"P1D"` | ISO 8601 duration string specifying how far back to import campaigns (e.g., P1D for 1 day, P7D for 7 days) |  |
| GTI_CAMPAIGN_ORIGINS | `array` |  | `All` `partner` `crowdsourced` `google threat intelligence` | `["google threat intelligence"]` | Comma-separated list of campaign origins to import, or 'All' for all origins. Allowed values: All, partner, crowdsourced, google threat intelligence | ```All```, ```partner```, ```google threat intelligence```, ```crowdsourced``` |
| GTI_CAMPAIGN_EXTRA_FILTERS | `array` |  | string | `[]` | Optional List of additional filters to add to query when fetching campaigns | ```name:Operation Shadow``` |
| GTI_CAMPAIGN_SUBENTITIES | `array` |  | `malware_families` `attack_techniques` `vulnerabilities` `threat_actors` `domains` `files` `urls` `ip_addresses` `software_toolkits` `reports` | `["malware_families", "attack_techniques", "vulnerabilities", "threat_actors", "software_toolkits"]` | Comma-separated list of sub-entity types to fetch and link for each campaign. An empty list disables sub-entity fetching entirely for campaigns, which can help reduce API quota usage. Allowed values: malware_families, attack_techniques, vulnerabilities, threat_actors, domains, files, urls, ip_addresses, software_toolkits, reports | ```malware_families,threat_actors```, `````` |
| GTI_IMPORT_VULNERABILITIES | `boolean` |  | boolean | `false` | Whether to enable importing vulnerability data from GTI |  |
| GTI_VULNERABILITY_IMPORT_START_DATE | `string` |  | Format: [`duration`](https://json-schema.org/understanding-json-schema/reference/string#built-in-formats) | `"P1D"` | ISO 8601 duration string specifying how far back to import vulnerabilities (e.g., P1D for 1 day, P7D for 7 days) |  |
| GTI_VULNERABILITY_GET_RELATED_SOFTWARES | `boolean` |  | boolean | `false` | Whether to enable importing related software data from vulnerability data |  |
| GTI_VULNERABILITY_ORIGINS | `array` |  | `All` `partner` `crowdsourced` `google threat intelligence` | `["google threat intelligence"]` | Comma-separated list of vulnerability origins to import, or 'All' for all origins. Allowed values: All, partner, crowdsourced, google threat intelligence | ```All```, ```partner```, ```google threat intelligence```, ```crowdsourced``` |
| GTI_VULNERABILITY_EXTRA_FILTERS | `array` |  | string | `[]` | Optional List of additional filters to add to query when fetching vulnerabilities. | ```name:CVE-2024``` |
| GTI_VULNERABILITY_SUBENTITIES | `array` |  | `malware_families` `attack_techniques` `threat_actors` | `["malware_families", "attack_techniques", "threat_actors"]` | Comma-separated list of sub-entity types to fetch and link for each vulnerability. An empty list disables sub-entity fetching entirely for vulnerabilities, which can help reduce API quota usage. Allowed values: malware_families, attack_techniques, threat_actors | ```malware_families,threat_actors```, `````` |
| GTI_IMPORT_MALWARE_FAMILIES | `boolean` |  | boolean | `false` | Whether to enable importing malware family data from GTI |  |
| GTI_MALWARE_FAMILY_IMPORT_START_DATE | `string` |  | Format: [`duration`](https://json-schema.org/understanding-json-schema/reference/string#built-in-formats) | `"P1D"` | ISO 8601 duration string specifying how far back to import malware families (e.g., P1D for 1 day, P7D for 7 days) |  |
| GTI_MALWARE_FAMILY_ORIGINS | `array` |  | `All` `partner` `crowdsourced` `google threat intelligence` | `["google threat intelligence"]` | Comma-separated list of malware family origins to import, or 'All' for all origins. Allowed values: All, partner, crowdsourced, google threat intelligence | ```All```, ```partner```, ```google threat intelligence```, ```crowdsourced``` |
| GTI_ENABLE_MALWARE_ALIASES | `boolean` |  | boolean | `false` | Whether to enable importing malware family aliases from GTI |  |
| GTI_MALWARE_FAMILY_EXTRA_FILTERS | `array` |  | string | `[]` | Optional List of additional filters to add to query when fetching malware families. | ```name:Emote``` |
| GTI_MALWARE_FAMILY_SUBENTITIES | `array` |  | `threat_actors` `attack_techniques` `vulnerabilities` | `["threat_actors", "attack_techniques", "vulnerabilities"]` | Comma-separated list of sub-entity types to fetch and link for each malware family. An empty list disables sub-entity fetching entirely for malware families, which can help reduce API quota usage. Allowed values: threat_actors, attack_techniques, vulnerabilities | ```threat_actors,attack_techniques```, `````` |
| GTI_IMPORT_THREAT_ACTORS | `boolean` |  | boolean | `false` | Whether to enable importing threat actor data from GTI |  |
| GTI_THREAT_ACTOR_IMPORT_START_DATE | `string` |  | Format: [`duration`](https://json-schema.org/understanding-json-schema/reference/string#built-in-formats) | `"P1D"` | ISO 8601 duration string specifying how far back to import threat actors (e.g., P1D for 1 day, P7D for 7 days) |  |
| GTI_THREAT_ACTOR_ORIGINS | `array` |  | `All` `partner` `crowdsourced` `google threat intelligence` | `["google threat intelligence"]` | Comma-separated list of threat actor origins to import, or 'All' for all origins. Allowed values: All, partner, crowdsourced, google threat intelligence | ```All```, ```partner```, ```google threat intelligence```, ```crowdsourced``` |
| GTI_ENABLE_THREAT_ACTOR_ALIASES | `boolean` |  | boolean | `false` | Whether to enable importing threat actor aliases from GTI: alternative names, then the names of the actors GTI merged into the threat actor (merged_actors). |  |
| GTI_THREAT_ACTOR_EXTRA_FILTERS | `array` |  | string | `[]` | Optional List of additional filters to add to query when fetching threat actors. | ```name:APT28``` |
| GTI_THREAT_ACTOR_SUBENTITIES | `array` |  | `malware_families` `attack_techniques` `vulnerabilities` `software_toolkits` | `["malware_families", "attack_techniques", "vulnerabilities", "software_toolkits"]` | Comma-separated list of sub-entity types to fetch and link for each threat actor. An empty list disables sub-entity fetching entirely for threat actors, which can help reduce API quota usage. Allowed values: malware_families, attack_techniques, vulnerabilities, software_toolkits | ```malware_families,attack_techniques```, `````` |
| GTI_IMPORT_REPORTS | `boolean` |  | boolean | `true` | Whether to enable importing report data from GTI |  |
| GTI_REPORT_IMPORT_START_DATE | `string` |  | Format: [`duration`](https://json-schema.org/understanding-json-schema/reference/string#built-in-formats) | `"P1D"` | ISO 8601 duration string specifying how far back to import reports (e.g., P1D for 1 day, P7D for 7 days) |  |
| GTI_REPORT_TYPES | `array` |  | `All` `Actor Profile` `Country Profile` `Cyber Physical Security Roundup` `Event Coverage/Implication` `Industry Reporting` `Malware Profile` `Net Assessment` `Network Activity Reports` `News Analysis` `OSINT Article` `Patch Report` `Strategic Perspective` `TTP Deep Dive` `Threat Activity Alert` `Threat Activity Report` `Trends and Forecasting` `Weekly Vulnerability Exploitation Report` | `["All"]` | Comma-separated list of report types to import, or 'All' for all types. Allowed values: All, Actor Profile, Country Profile, Cyber Physical Security Roundup, Event Coverage/Implication, Industry Reporting, Malware Profile, Net Assessment, Network Activity Reports, News Analysis, OSINT Article, Patch Report, Strategic Perspective, TTP Deep Dive, Threat Activity Alert, Threat Activity Report, Trends and Forecasting, Weekly Vulnerability Exploitation Report | ```All```, ```Actor Profile,Malware Profile```, ```Threat Activity Alert``` |

| GTI_INDICATOR_SCORING | `string` |  | `threat_score` `gti_derived` `average_detection` | `"threat_score"` | Strategy used to compute the score of IOC indicators and observables. 'threat_score': GTI threat score, then GTI confidence score, then Mandiant confidence score (deprecated by GTI). 'gti_derived': computed from the GTI verdict and severity. 'average_detection': computed from the share of AV engines flagging the IOC (last_analysis_stats). When the selected strategy has no data for an IOC, 'threat_score' is used. |  |
| GTI_INDICATOR_MIN_VERDICT | `string` |  | `any` `suspicious` `malicious` | `"any"` | Lowest GTI verdict for which an IOC gets an indicator. 'any': every IOC. 'suspicious': suspicious and malicious IOCs. 'malicious': malicious IOCs only. IOCs below it, or without a verdict, are imported as observables only, and are skipped by the IOC deltas feed, which only imports indicators. |  |
| GTI_IOC_TAGS_AS_LABELS | `boolean` |  | boolean | `false` | Whether to add the GTI tags of IOCs (e.g. 'peexe', 'self-signed'), and the GTI threat category of files (e.g. 'trojan'), as labels of their indicators and observables, for every data collection and the IOC deltas feed (tags only). Tags describe file types, behaviours and infrastructure traits, and can create many labels. |  |
| GTI_RELATIONSHIP_DESCRIPTIONS | `boolean` |  | boolean | `false` | Whether to describe on each relationship why the connector created it: 'Stated by GTI' for a GTI association, quoting the GTI relationship, or 'Inferred by the connector' for co-occurrence links, naming the report or campaign. Disabled by default: OpenCTI identifies a relationship by its type, source, target and dates, so these descriptions can overwrite one written by an analyst or another source, depending on the connector confidence level. |  |
| GTI_IP_LINK_TO_ASN | `boolean` |  | boolean | `false` | Whether to create the autonomous system of IP address IOCs, with its number, owner and registry, and link the IP to it with 'belongs-to'. Applies to the IPs of every data collection; the IOC deltas feed only imports indicators, so it is not affected. |  |
| GTI_IP_LINK_TO_COUNTRY | `boolean` |  | boolean | `false` | Whether to link IP address IOCs to the Country location of their GTI country code with 'located-at'. Applies to the IPs of every data collection; the IOC deltas feed only imports indicators, so it is not affected. Unknown country codes are skipped. |  |
| GTI_IOC_IMPORT_THRESHOLD | `integer` |  | `1 <= x ` | `null` | Maximum number of IOCs (files, domains, URLs, IP addresses) a report or campaign may reference for its IOCs to be fetched. Above it, the IOC sub-entities of that report or campaign are skipped, which saves the API quota they would use; its other sub-entities are still imported. Leave unset to always fetch IOCs. |  |
| GTI_IOC_LINK_TO_THREATS | `boolean` |  | boolean | `false` | Whether to link the IOCs of a report or campaign to the intrusion sets and malware of that same report or campaign (and to its campaigns, for reports): 'indicates' from indicators, 'related-to' from observables. These relationships come from co-occurrence in the same container, not from a GTI attribution, and their number is IOCs times threats: combine with ioc_import_threshold on large containers. |  |
| GTI_INTRUSION_SET_LINK_TO_CAPABILITIES | `boolean` |  | boolean | `false` | Whether to link the intrusion sets of a report or campaign to the malware, tools and attack patterns ('uses') and the vulnerabilities ('targets') of that same report or campaign. These relationships come from co-occurrence in the same container, not from a GTI attribution. |  |
| GTI_EXTENDED_DESCRIPTIONS | `boolean` |  | boolean | `false` | Whether to append the GTI details that have no dedicated OpenCTI field to descriptions, as Markdown bullet lists. IOC indicators and observables: GTI assessment (verdict, severity, threat score, summary, contributing factors), the threat severity of files, plus the country, autonomous system and network of IP addresses, except what ip_link_to_country and ip_link_to_asn import as linked objects. Vulnerabilities: risk rating, exploitation state, exploit availability, exploitation consequence and vectors, remediation priority, exploitation dates, CISA KEV dates and ransomware use, mitigations. Malware families: targeted operating systems and detection names. The GTI description is kept and the details follow it. Can overwrite descriptions edited in OpenCTI, depending on the connector confidence level. |  |
